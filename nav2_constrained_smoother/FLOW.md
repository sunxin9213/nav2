# nav2_constrained_smoother 整体流程

## 一、包定位

带约束的路径平滑器插件：在平滑的同时**保持路径的碰撞安全性和与障碍的相对拓扑**（不会把路径"平滑进"障碍物，也不会穿过原本绕开的狭窄缝隙），并提供曲率/朝向约束。

## 二、核心组件

| 组件 | 文件 | 职责 |
|---|---|---|
| `ConstrainedSmoother` | `constrained_smoother.cpp` | 实现 `nav2_core::Smoother` |
| `smoother_utils` | `smoother_utils.cpp` | 核心算法：ceres 优化问题构建、直线路径恢复、可行性检查 |

## 三、主流程

```
smooth(path, max_duration):
    1. 预处理: 路径重采样、坐标系转换
    2. 构建 ceres 优化问题，路径点为优化变量:
        ├─ 平滑项: 相邻点二阶差分（曲率）最小化
        ├─ 数据项: 距原始路径不要偏太远（w_data）
        ├─ 碰撞项: 点进入膨胀区/障碍 → 大惩罚（硬约束成本）
        └─ 可选: 朝向约束 / 保持起点终点
    3. 求解（带 max_duration 截断）
    4. 后处理: 平滑后逐点碰撞检查
        ├─ 可行 → 返回
        └─ 不可行（局部失败）→ 对失败段恢复为原始折线
           （use_ceres / revert 参数控制策略）
    5. 曲率检查: 超过最小转弯半径的段 → 调整或还原
```

## 四、数据流

```
原始路径 ──→ ceres 优化(平滑+碰撞+数据项) ──→ 不可行段还原 ──→ 平滑且安全的路径
                 ↑ costmap（碰撞惩罚项）
```

## 五、与其他包的关系

- 作为插件被 `nav2_smoother` 服务器加载
- 与 `SimpleSmoother` 的本质区别：是否保证"平滑后仍然无碰撞且拓扑不变"
- 与 `nav2_smac_planner` 内部 smoother 的区别：那是搜索后的即时平滑，这里是独立服务可对任意路径使用
